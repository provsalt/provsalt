## 私がAIの過熱ぶりを個人的に嫌う理由
まず前置きしておきたいのですが、生成AIには本当に良い使い道があると思っています。ただ、最近ではAIという言葉が、何でも魔法のように直せる動詞みたいに飛び交わない日はないように感じます。

このことについてはずっと前から愚痴りたいと思っていましたが、もう書かずにはいられないほど腹が立ってきたのだと思います。

AIは何でも解決できないし、企業もそれを分かっています。それなのに、なぜプロセスのあらゆる段階で皆にAIを使わせようとしているのでしょうか。個人的にはこれは強欲さなのかもしれないと感じますが、株主を喜ばせたり、ベンチャーキャピタリストに次のスタートアップへ資金を投げ込ませたりする以外に、AGIですらなく、人間なら一秒で計算できる単純な問題さえ解けないものへ大量のGPUと電力を注ぎ込む正当な理由はありません。

では、私がAI、あるいはいわゆる人工知能の利用を自分で制限しようとしている理由に入ります。

## 文字どおり、頭が悪くなる
ここ数年、GitHub Copilotがリリースされてからずっと拡張機能を有効にし、とても忠実なユーザーでした。しかし、これはまったく最善の考えではないかもしれないと気付きました。ツールに頼るようになり、自分のスキルには頼らなくなるからです。

これは、補完のためにTabキーを押すことに頼りがちになり、思考力が落ちていくような問題を生みます。IntelliSenseのような従来型の自動補完と違い、IDE上でどの候補を補完するか選ぶ手間すらありません。端的に言えば、自分が実際に何を書いているのかを考えず、気に入らない結果を出すかもしれないAIのコードレビュアーになってしまうのです。

この問題は、コーディングを始める人にとってはさらに悪いと思います。私が「AIに聞け」と呼びたいもので、問題が起きて解決方法がまったく分からなければ、AIに直してもらえばいい、というものです。

必ずしも悪いことではありません。従来の検索エンジンにどうプロンプトを出せばいいか本当に分からない人たちからのDMを減らすのに役立ちますし、そこはLLMが輝くところです。検索エンジンをいじくり回さずに、自然言語を使えます。

例えば、AI以前にGolangで構文エラーの問題があったら、私は検索エンジンにこう入力していました。

*"syntax error golang debug"*

一方で今なら、エラー全体をLLMに貼り付けて、なぜエラーなのかを聞くだけです。たいていは何なのかを特定してくれます。

問題は、やることが全部を貼り付けてAIに解決させるだけなら、エラーやスタックトレースさえ読みたくなくなることです。これを私は思考停止の問題解決と呼びたいです。次回は自分でどう防ぎ、どう直せるかを考えるためのやり取りも、批判的思考も、基本的にゼロです。私に反対する人などもいるかもしれませんが、ほとんど何も分かっていない状態で、LLMが実際に何を説明しているのか理解しようとしている人を見たことはありますか？ 初心者／ジュニア開発者にとっては、何も理解せずに外国語を読もうとするようなものです。

そうです。経験がほぼゼロの開発者なのに、hello worldを書いてもらうためにchatgptへプロンプトを出している人に出会ったことがあります。ドキュメントを読めば、これは5分で分かるはずです。

[2024年のstackoverflow調査](https://survey.stackoverflow.co/2024/ai#sentiment-and-usage-ai-sel-learn)によると、コーディングを学んでいる回答者の63%以上が助けを得るためにAIを使っており、これは私の意見では、まともにコンピューターを操作できなくなったiPad世代のようになっていくでしょう。

人々、特に学生は、以前ほど文章を読もうとしません。とはいえ、LLMから学べることもあると思います。たとえば、なぜ、どのように実装されているのかを自分に積極的に問いかける「チェーン・オブ・ソート」です。ChatGPTや**ここにもっとコーディングが得意な新しいLLMを挿入**が出したコードを、盲目的にコピー＆ペーストするだけではありません。

私は、どこへ行くにも電卓を持ち歩けるわけではないと言って、将来間違いを証明されるような昔の教師の一人かもしれません。しかし、少なくともトラブルシューティングする能力を誰かが持つことは重要だと思います。これこそが優れたソフトウェアエンジニアを価値あるものにすることであり、あの暗算の達人たちがその職業で高く評価されるのと同じです。

私が持っている最もひどい例の一つは、three.jsで起きた、ものすごく単純なパフォーマンス問題をトラブルシューティングしようとしたときです。LLMは異常なパターンの検出が得意なので、そこにかけてみました――この一件だけは例外でしたが……。

```js
  const clock = new THREE.Clock();
  const fps = 60;
  const interval = 1000 / fps;
  let lastTime = 0;

  function animate() {
    requestAnimationFrame(animate);

    const time = Date.now();
    if (time - lastTime >= interval) {
      lastTime = time;
      controls.update();
      renderer.render(scene, camera);
    }

    const deltaTime = clock.getDelta();

    if (gameState.mixer) {
      gameState.mixer.update(deltaTime);
    }

    if (gameState.character) {
      characterMovement(deltaTime);
      updatePhysics(deltaTime, ground, groundBody, hitboxMesh);
    }
  }
```

普通に見えるでしょう？ 違います。問題は、lastTimeとintervalを比較するif文のロジックにありました。ただしこれは、intervalに達していないにもかかわらず、更新する必要のない他の関数まで更新され続けるという、初心者的なミスです。

いいえ、chatgptとclaudeはこれを見つけられませんでした。私はAIにかなり依存していたので、まず自分で解こうとはあまりせず、最終的にAIがこれを「直して」くれるようにプロンプトを試していました。しかし、1時間うまくいかなかったあと、自分でプロファイラを実行することにして、エラーがanimateループにあると突き止めました。

ただ、このひどいコードを書いたのは私ではありません。レンダリングしないフレームでも非常に負荷の高いupdatePhysicsを呼び出していました。もし私が書いたなら、Gitにpushする前に、動作がひどく遅いことに気付いていたはずです。

では、この例からの私の結論は、AIを正しい方向へ導こうとプロンプトに1時間を費やさないことです。if文を動かすだけのような単純なことすら、LLMにはできません。

## 人々はAIを評価しすぎている
前にも述べたように、人々はAIの現在の状態を過大評価しすぎています。彼らの大半は、ニューラルネットワークが表面的にすらどう動くのか分かっていません。私はこの話題についてそれほど詳しいわけではありませんが、あまり信頼すべきでないと自分に思い出させるには十分です。特に、安全かどうかを確認せずにターミナルで使うべきではありません。AIの過熱ぶりについて言えるのは、暗号資産の過熱ぶりにそっくりだということです。crypto brosもAI brosも、AIと暗号資産の分野で自分たちが何を話しているのか分かっていません。

Twitterや、実際にはオンラインのどこにでも、ソフトウェアエンジニアはもう必要なく、皆がdevinか何か、AIエージェントの新しい流行を使うべきだと主張したがるタイプの人たちがいつもいます。そんなことはまったくなく、theprimeagenの[devinの使用](https://www.youtube.com/watch?v=QOJSWrSF51o)を見たならなおさらです。

> これは見ていてものすごく面白かったです。時間があれば、この2時間の動画をぜひ見てください。

上の動画はAIの性質について多くを物語っていると思います。AIは幻覚を起こすし、現在の技術でこれを解決する方法はありません。

もう一つ私の愚痴ですが、人々はopenaiのモデルであるo3について話し、それをagiと呼んでいます。しかし、agiのベンチマークの一部に合格できたとしても、これはagiではありません。

一部のプロジェクトマネージャーも、そもそも技術者ではないのでコーディングから本当にかけ離れています。何が起きるかというと、自前のデータで、その機能を持つchatgptクローンを10ストーリーポイント未満で作れると期待するのです。

人々はこれが生死を分ける状況であるかのように振る舞うのをやめるべきです。これはゴールドラッシュのようなもので、あなたのデータを売る人、あるいはチップを売る人が勝つことになります。時間をかけて、Windowsを更新するたびに新しいAI機能を押し付けられたと感じずに済む、使う人の邪魔をしない形で実装してください。私が必要としているのは、AIだとすら気付かないほど上手く作られたAIだけです。半端なchatgptラッパーはもう必要ありません。

AGIが来た日とは、AI企業が全社員を解雇して自前の「有能な」AIに置き換える日です。そして、こんなことが今後5年以内に起きるわけがありません。

## 結論
これがあまりに長い愚痴になっていなければいいのですが、私の理由の大半は開発者コミュニティで広く共有されていると思います。私はただ、このAIトレンドについて自分の声を発信しているだけで、お金が尽きたら本当に消えてほしいと思っています。

あ、待って。何を言っているんでしょう、私は。AIと何の関係もない製品まで、業界がAIと呼ぶのをやめるわけがありません。

AIツールへの依存を減らす旅の途中にいますが、これはあまりに習慣になっていて、まるで薬物のようにやめるのが本当に難しいです。この投稿が、AIの利用を最小限に減らす、あるいは完全に使うのをやめるよう、人々を説得できたならと思います。インターネット全体がAIになる前に、AIを止める運動があれば本当に素晴らしいでしょう。
